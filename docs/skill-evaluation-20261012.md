# recall-eval Skill 真实模型对照评测

日期：2026-10-12。模型路由：`DMXAPI-deepseek-v4-flash`，响应自报 `deepseek-v4-flash`。
这是一项**诊断 Skill 的显式上下文加载消融实验**：让真实模型诊断合成运行记录。
测量对象是诊断标签准确性，不是线上 RAG 回答准确率。

## 实测结果

24 个自建合成案例，每个案例每组重复 2 次，基线组和 Skill 组各 48 次，合计 **96 次真实请求**。
全部返回且符合 JSON 格式，未截断，没有自动重试或筛除失败。
以“该次输出的全部标签与人工预期完全一致”为主指标。

| 指标 | 基线：完整任务说明 | 加载 recall-eval Skill |
| --- | ---: | ---: |
| 完整诊断正确率（主指标） | 42/48，87.5% | 44/48，91.7% |
| 缺陷检出率（micro recall） | 36/40，90.0% | 38/40，95.0% |
| 缺陷漏检次数 | 4 | 2 |
| 缺陷诊断精确率（micro precision） | 36/38，94.7% | 38/40，95.0% |
| 正常案例误报 | 2/14，14.3% | 2/14，14.3% |
| 输出格式有效率 | 48/48，100% | 48/48，100% |
| 平均请求耗时 | 3.327 秒 | 3.325 秒 |
| 服务商报告的输入 Token 总量 | 31,330 | 89,890 |
| 服务商报告的总 Token 用量 | 33,684 | 92,344 |

本次观察到主指标提高 **4.17 个百分点**、缺陷检出率提高 **5 个百分点**。
Skill 的总 Token 用量约为基线 **2.74 倍**；耗时基本持平，不能据此声称更快或更便宜。
Token 为上游报告值，没有核实实际账单金额。

## 实验如何固定

- [Skill](../skills/recall-eval/SKILL.md) 组织了上下文重建、分维度诊断、状态迁移核对和基于证据报告的流程，详细规则放在 [参考资料](../skills/recall-eval/references/failure-modes.md)。
- [案例集](../skills/recall-eval/evals/cases.json) 覆盖召回、回答支持、引用、执行、记忆写入和工作区隔离六个维度，另含正常行为与证据不足。24 个案例中，16 个有确定缺陷、7 个正常、1 个信息不足。
- [预先固定的协议](../skills/recall-eval/evals/protocol.json)：temperature=0、max_tokens=650、每组重复 2 次、最多 96 次请求，种子为 20261012。
- 两组使用同一模型、观测、完整标签定义、输出格式和评分器。Skill 组额外加载 SKILL.md 正文及参考资料。基础组拥有完整规则，不人为弱化。
- 同一案例、同一次重复的两组请求相邻执行，组内先后顺序随机；每次都是独立会话。标准答案只用于评分，不发送给模型。
- 首次模型调用前，冻结了全部输入、提示词、顺序、参数和脚本哈希。没有根据本轮结果修改 Skill、案例或判定规则。
- [评测器](../skills/recall-eval/scripts/run_eval.py) 在发送前记录尝试，断点续跑只发送未尝试的请求；解析失败、缺失和接口错误计入主指标分母。连续三次接口错误停止。
- Windows Python 3.12 和服务器 Python 3.8 均通过 **13 项离线测试**；Skill 格式校验通过。远端评分下载后，本地重新计算与全部原有指标一致。

本次实际通过 API 显式加载诊断指导。未测量客户端的 Skill 自动发现、触发准确率、工具调用成功率或自主修改代码的能力。

## 哪些案例变化了

48 对结果中：42 对都正确，2 对由错误变正确，4 对都错误，没有正确变错误的配对。
**2 次改善来自同一个案例 C09 的两次重复，而不是两个独立场景。**

| 案例 | 预期 | 基线表现 | Skill 表现 |
| --- | --- | --- | --- |
| C09：有相关记忆但未召回，最终回答编造金额并使用不存在的引用 | 召回遗漏 + 无支持回答 + 引用错误 | 两次均漏报召回遗漏 | 两次均识别全部三项 |
| C03：上下文记录一个金额，最终回答以同一引用写出另一个无支持金额 | 无支持回答 + 引用错误 | 两次均漏报引用错误 | 两次均漏报引用错误 |
| C12：空记忆；错误草稿已被拦截，最终回答合理拒答 | 无缺陷 | 两次分别误报引用错误、无支持回答 | 两次均臆测“本应存在记忆”，误报召回遗漏 |

C03 和 C12 的原始错误均完整保留。当前指导对多缺陷联合判断有帮助，但仍未解决错误草稿与最终输出的稳定区分，以及同一事实同时违反回答和引用规则时的漏报。

按 24 个独立案例分簇、保留每例两次重复的 bootstrap 描述区间为 **[0.0, 12.5] 个百分点**（6,000 次重采样）。
区间包含 0，样本小且重复相关，不能宣称统计显著提升。
它也不涵盖案例设计偏差、跨模型变化等不确定性。

从仓库根目录离线重算，不会调用模型：

```sh
python -c "import gzip,pathlib,shutil; s=pathlib.Path('docs/skill-evaluation-20261012'); d=pathlib.Path('tmp/skill-eval-replay'); d.mkdir(parents=True,exist_ok=True); (d/'manifest.json').write_bytes(gzip.decompress((s/'manifest.json.gz').read_bytes())); shutil.copyfile(s/'manifest.sha256',d/'manifest.sha256'); shutil.copyfile(s/'events.jsonl',d/'events.jsonl')"
python skills/recall-eval/scripts/run_eval.py score --out tmp/skill-eval-replay
python -m unittest discover -s skills/recall-eval/scripts -p test_eval.py
```

如需新的真实实验，先 `prepare` 一个新的输出目录，再 `run`；凭据从私有配置文件读取，绝不写入 Skill 或报告。
冻结输入便于审计；即使参数相同，服务商模型路由及生成结果也未必完全一致。

## 简历可用表述

> 为记忆型 AI Agent 设计 recall-eval 诊断 Skill 与配套 Evaluation Harness，沉淀召回、生成、引用、记忆写入等六维检查流程；在 24 个自建合成案例、96 次真实模型调用的配对消融评测中，完整诊断正确率由 87.5% 提升至 91.7%，缺陷检出率由 90% 提升至 95%，支持输入冻结、断点记录和结果复算。

面试解释时需要同时说明：提升来自一个复合缺陷案例的两次重复，正常案例误报没有下降，总 Token 用量约增至 2.74 倍。
可以称“本组合成评测中的观察结果”，不能写成“线上回答准确率提高至 91.7%”或“显著优于基线”。

这些是作者构造、作者标注的案例，Skill 与案例由同一作者设计，没有独立盲测集；证据文本被保存，但评分只检查标签集合，未自动评估解释质量。
后续迭代应保留本轮作为开发集记录，在独立案例集上验证 C03/C12 的修复及跨模型稳定性，再决定是否替换当前版本。
